# FoodieGo – MVP Requirements

## 1. MVP Overview

The Minimum Viable Product (MVP) of FoodieGo focuses on the core features required for customers, administrators, and restaurant owners to use the food ordering application.

The MVP includes restaurant browsing, menu viewing, user registration and login, cart management, order placement, order history, and restaurant/menu management.

## 2. MVP Requirements Table

| Feature | User | Expected Behaviour |
|---|---|---|
| Restaurant List | Customer | Customer can view a list of available restaurants. |
| Menu Items | Customer | Customer can select a restaurant and view its available menu items. |
| Register / Login | Customer | Customer can create an account and log in to the FoodieGo application. |
| Cart / Quantity | Customer | Customer can add menu items to the cart and increase or decrease item quantities. |
| Place Order | Customer | Customer can review the cart and place an order. |
| Order History | Customer | Customer can view previously placed orders. |
| Manage Restaurants | Administrator / Restaurant Owner | Authorized users can add, update, and manage restaurant information. |
| Manage Menu Items | Administrator / Restaurant Owner | Authorized users can add, update, and remove menu items. |

## 3. Features Excluded from the MVP

The following features are intentionally excluded from the initial MVP:

- Online payments
- Live order tracking
- Coupons and discount systems
- Push notifications

These features can be considered for future versions of FoodieGo.

## 4. MVP Goal

The main goal of the FoodieGo MVP is to provide a basic food ordering workflow where customers can discover restaurants, view menus, manage a cart, place orders, and view their order history, while administrators and restaurant owners can manage restaurants and menu items.
